02 / Getting the data ready

Data Inspection and Cleaning

After using head() to inspect the first five rows of the data, I focused on the columns u, g, r, i, and z. The u filter was ultraviolet, g was green, r was red, i was near infrared, and z was infrared. These measurements came from the Sloan Digital Sky Survey (SDSS) telescope camera. Each reading recorded how bright an object looked through that filter. The readings are expressed as magnitudes, so lower numbers mean the object appeared brighter.

A peek at the filter readings

The five magnitude columns shown in the notebook’s first rows.

In class during Lesson 2, we learned about flux, which is how much light energy reaches a given area each second. Lesson 7 helped me see why I had five brightness readings for the same object. Each filter picks up a different range of wavelengths on the electromagnetic spectrum.

At first, I thought a single magnitude told me what color an object was. I was shocked to learn that astronomers describe color using the difference between two magnitudes. For example, if g - r is positive, then r is lower than g. That means the object looks brighter through the red filter than through the green one, and a larger g - r means it’s redder by that measure.

I noticed the dataset included quasars alongside stars and galaxies. A quasar is an extremely bright active galactic nucleus powered by a supermassive black hole at the center of a galaxy. Since my project focused on telling stars and galaxies apart, I went ahead and removed the quasars.

Then I removed rows with missing filter readings, including values like -9999 that marked missing data. Those values could throw off the model. After cleaning the data, I went from 100,000 rows to 81,038.

03 / Looking at the measurements

Preliminary Graphing

I wanted to see if there were any blatantly obvious differences in filter readings between stars and galaxies, so I made some preliminary histograms. The first step was to split the data into two groups, one for stars and one for galaxies.

Long story short, I made the histograms using what I’d learned in a class at UChicago, but I had to first figure out how to compare the two groups fairly.

To make things more efficient, I wrote one function that made a chart and used a for loop to call it for each filter. The function took the filter as an argument, x, so the same code could make all five charts.

I gave each group a total weight of 100, spread evenly across its objects. That way, each bar showed the percentage of stars or galaxies in that bin. For the shared range, I used the lowest and highest readings across both groups so their bins lined up.

def histmaker(x):

04 / Learning from examples

Training the model

Graph of linear and logistic regression

Despite its name, logistic regression is a classification algorithm rather than a regression algorithm.

Logistic regression uses the sigmoid, aka the S-shaped function, to estimate the probability that an object belongs to a certain group. It’s a supervised learning method because it learns from examples where we already know the answers. In my case, the inputs, called features, were brightness readings from each filter. The answers, called labels, were star or galaxy.

The model multiplies each filter reading by its own weight, adds those results together, and adds a bias to get a score. The sigmoid turns that score into a probability. During training, the model adjusts its weights and bias to reduce log loss, which gives a bigger penalty when the model is confidently wrong. And boom, you have a trained model. Give it the filter readings for a new object, and it predicts whichever label it thinks is more likely.

Now, obviously, we need to split the data into a training set and a test set. If we test the model on the same data it trained on, we only see how well it does on examples it’s already seen. A separate test set shows how well it handles new examples.

For each split, I randomly assigned 60% of the unique object IDs to training and the other 40% to testing. Rows with the same ID stayed together, and I tested all 16 filter combinations on the same rows within each split.

From there, I honestly tried to build logistic regression from scratch after researching the math behind it. After spending a while on it, I gave up and switched to scikit-learn, with some help from my friend named Claude.

I ran the experiment across five different train/test splits so the results wouldn’t depend on one fluky split. Each split tested tens of thousands of objects, so I reported the results per 100 for readability.

06 / What the filters did

Conclusion

Right after seeing the confusion matrices, I was surprised by the results. If the numbers aren’t intuitive yet, don’t worry. I’ll show them in a dot plot in a second.

Across the five splits, ultraviolet was the best single filter at identifying stars, catching just 9.3%. All five filters caught the most stars overall, at 49.2%. Green and near infrared came close at 48.6%.

The most shocking part? Green and infrared caught 48.4% of stars, compared with 49.2% for all five filters. The pair also correctly identified 95.2% of galaxies, compared with 94.4% for all five. Of the combinations I tested, green and infrared was my two-filter answer. It caught almost as many stars as all five filters and made fewer mistakes on galaxies! Both models still missed slightly more than half the stars though.

Here’s the dot plot. Higher means better sensitivity, or a higher percentage of actual stars correctly identified. Farther left means better specificity because a smaller percentage of actual galaxies were mistaken for stars. Look at g + z, g + i, and all five (ugriz). They’re nearly level, and g + z sits farthest left of the three.
